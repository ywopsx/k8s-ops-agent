README에 정의된 Unit 2: *알림이 오면 상태를 조회하고 원인 후보와 런북을 Slack 스레드에 남김.*

## 이미 정해진 것 (질문하지 않음)

`00-context.md`에서 정한 내용이다. 바꾸려면 그 문서부터 고친다.

- 환경: kind에 Prometheus, Alertmanager, Grafana, Loki를 띄운다. 실제 AWS 계정에서는 실행하지 않는다.
- 입력: Alertmanager가 에이전트 webhook을 호출한다 (Slack 게시 방식은 Q7에서 정한다)
- 조회: PromQL, LogQL, kubectl을 읽기 전용으로 병렬 조회한다. 자동 조치는 하지 않는다.
- 출력: 원인 후보와 런북을 Slack 알림 스레드에 답글로 남긴다.
- LLM: Anthropic API. API 키는 `.env` 환경 변수로만 관리한다. 외부 패키지는 optional-dependencies로 분리한다.
- Unit 1 연동: MCP stdio 서버의 `run_preflight` 도구를 불러 쓴다.
- 평가: 시나리오마다 정답 원인을 정해 두고 정확도, 걸린 시간, 토큰 비용을 측정한다. 런북을 줄 때와 안 줄 때를 비교한다.
